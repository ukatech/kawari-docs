# 華和梨 7 互換モード

華和梨 Phase 9.3.0 (Core 4.3.0) 以降は、華和梨 Phase 7.5.0 のゴーストを、辞書を書き換えずに動かせる。この動作を「7 互換モード」と呼ぶ。この章は 7 互換モードの仕様を定める。基準は Phase 7.5.0 (2003/02/16) の実装で、以下の「7.5.0」はこのバージョンを指す。

7 互換モードは通常の動作 (Phase 8・9 の辞書) とは別の動作モードである。通常の動作は変わらない。

## モードの決まり方

- モードはゴースト単位で決まる。`shiori.dll` の読み込み (`load` / `loadu`) のときに一度だけ決め、途中で切り替えない。
- ゴーストのフォルダに `kawarirc.kis` が無く、`kawari.ini` があるとき、7 互換モードで動く。
- `kawarirc.kis` があるときは、`kawari.ini` があっても通常の動作で動く。
- 辞書のファイルごとにモードを混ぜることはできない。7 互換モードで読むファイルは、すべて 7 の辞書として読む。例外は次の節の「9 の文法を取り込む範囲」だけである。
- 幸水 (`kosui`) も同じ規則でモードを決める。引数に `.ini` で終わるファイル名を渡したときは、7 互換モードで読む。

## kawari.ini

`kawari.ini` には 1 行に 1 つの設定を `キー : 値` の形で書く。行頭が `#` の行と空行は無視する。`:` が無い行は行全体をキーとして扱う。キーの前後と値の前後の空白は取り除く。

| キー | 値 | 動作 |
|---|---|---|
| `dict` | ファイル名 | 辞書ファイルを読む。`kawari.ini` を読み終えてから、書かれた順に読み込む |
| `include` | ファイル名 | 別の ini ファイルを、その位置で読み込む |
| `text` | エントリ ファイル名 | テキストファイルを 1 行ずつ `エントリ.1` `エントリ.2` ... に読む (`textload` と同じ) |
| `adddict` | エントリ 単語 | エントリに単語を追加する |
| `set` | エントリ 単語 | エントリの内容を捨てて、単語 1 つにする |
| `saori` | DLL , 別名 [, オプション] | SAORI を登録する。オプションは `preload` / `loadoncall` (既定) / `noresident` |
| `randomseed` | 数 | 乱数の種を決める |
| `security` | 0〜3 | セキュリティレベル (既定は 2。「セキュリティ」の節を参照) |
| `locale` | 文字コード名 | 辞書の文字コードを指定する。Shift_JIS・UTF-8・EUC-JP・ISO-2022-JP・EUC-KR・GB2312・Big5・ISO-8859-1 を扱える。名前の書き方 (別名、大文字小文字、`-` `_` `.` と空白の無視) は [textload_charset](../kis/textload_charset.md) と同じ。暗号化行の復号結果も、この文字コードで読む |
| `debug` | `log` または `debugger` | `log` は `kawari.log` に、エラー・警告と、`OnMouseMove` 以外の要求と応答を記録する。`debugger` はデバッグ用のイベント `ShioriEcho` と `KawariCommand` を有効にする |

`kawari.ini` と辞書を読み終えたあと、`system.OnLoad` を評価する。`security` が 3 未満のときは、`resource.homeurl` を書き込み禁止にする。

## 辞書の書式

辞書は 1 行に 1 つの定義を書く。行の先頭によって、次のように扱う。

- `#` で始まる行はコメントである。
- `:` で始まる行は 7.5.0 ではプリプロセッサの行だった。7 互換モードでは何もせずに読み飛ばす。
- `[` で始まる行はマッチエントリである。`["単語", "単語", ...] : 応答` と書く。応答は、COMMUNICATE の入力 (`system.Sentence`) にすべての単語が含まれるときの候補になる。同じ単語の並びのマッチエントリが複数あるときは、応答を 1 つのエントリにまとめる。
- `!` で始まる行は暗号化行である。`!KAWA0000` の形式を復号して、1 行の辞書として読む。
- ファイルの 1 行目が `[SAKURA]` のときは、ピロ形式として読む。`#` で始まる行がラベルで、次の行が単語である。単語は `piro.ラベル` のエントリに入り、`pirocall` で呼び出せる。
- それ以外の行は `エントリ名 [, エントリ名]... : 単語 [, 単語]...` の形の定義である。単語はカンマで区切る。複数のエントリ名を書いたときは、全部のエントリに同じ単語を追加する。単語の前後の空白は取り除く。

辞書の文字コードは、BOM があれば UTF-8 とする。BOM が無いときは、`kawari.ini` に `locale` があればその指定に従い、`locale` も無ければ内容から UTF-8 か Shift_JIS かを判定する。BOM を `locale` より優先するのは、`save` / `savecrypt` が UTF-8 BOM 付きで書くためである (`locale : Shift_JIS` のゴーストでも、保存し直したセーブデータが文字化けしない)。

## エントリ名

7 互換モードのエントリ名は平坦な文字列である。通常の動作のように、名前を `.` で階層に分けない。したがって `dots` `dots.` `dots..x` `dots.x` は、すべて別のエントリである。末尾や連続の `.` も省略されない。`@` で始まる名前もローカルなエントリにならず、ふつうのエントリである。

エントリ名に使える文字は、半角の英数字、`_`、`.`、`-` (先頭を除く)、`@`、半角カナを除く ASCII 以外の文字である。

イベント名・リソース名からエントリ名を作るときは、ASCII の英数字と、ASCII 以外の文字 (半角カナを除く) をそのまま使い、それ以外の文字を `.` に置き換える。

## 字句と単語

- 区切り文字は `: ; , ] ( ! & | )` である。空白は半角スペースとタブである。引用符は `"` だけである。マクロは `${` と `$(` である。
- 引用符で囲んだ範囲は、そのまま文字列になる。中で展開は行わない。引用符を含めたいときは `\"` と書く。`\"` 以外のバックスラッシュはただの文字である。
- 区切り文字が意味を持つ場所は決まっている。`,` は辞書の行で単語を区切る。`;` と `)` はインラインスクリプトの中で文の終わりとインラインスクリプトの終わりを表す。それ以外の場所では、区切り文字はふつうの文字で、そのまま文字列になる (`a (b) c` の括弧も、文字として残る)。`]` は、どこでも文字である。
- `$` の後ろが `{` でも `(` でもないとき、`$` と次の 1 文字は、そのままの文字列になる。`$()` のように中身の無いインラインスクリプトも、文字列になる。

### エントリ呼び出し

- `${エントリ}` は、エントリの単語を 1 つ選んで評価する。同じ単語が複数あるときは、その数だけ選ばれやすくなる。選ぶ乱数は Phase 7.5.0 と同じ MT19937 で、`randomseed` が同じなら同じ順に選ばれる。
- `${エントリ&エントリ}` は、すべてのエントリに含まれる単語のうちから 1 つ選ぶ。`${別のエントリ}` だけの単語はその別のエントリの単語に展開して数える。
- `${N}` (N は数字で始まる) は履歴参照である。次の節を参照。
- 存在しないエントリや、単語の無いエントリは、空文字になる。

### 履歴参照

単語を評価するたびに、新しい履歴を作る。履歴に残るのは、その単語の中で評価した `${エントリ}` と `${エントリ&エントリ}` の結果だけである。`$( )` や `${N}` の結果は履歴に残さない。`${N}` は、N 番目 (0 から数える) の結果を返す。通常の動作とは数え方が違う (通常の動作では、`$` で始まる置換はすべて履歴に入る)。

`$( )` の中で履歴に積まれた結果は、`$( )` を終えるときに捨てる。`while` / `until` / `loop` / `foreach` の本体は繰り返しごとに新しい履歴で評価する。

## インラインスクリプト

`$(文; 文; ...)` の形で書く。文は空白で区切った単語の並びで、先頭の単語がコマンド名である。全部の文の結果を連結したものが、インラインスクリプトの結果になる。

次のコマンドは 7 互換モードでは構文として処理する。

| コマンド | 動作 |
|---|---|
| `if 条件 A` / `if 条件 A B` | 条件が真なら A、偽なら B を評価する (B が無ければ何もしない)。`else` は構文ではない。`if 条件 A else B` は要素が 5 つなので、何もしない (空文字) |
| `while 条件 本体` / `until 条件 本体` | 条件が真 (偽) の間、本体を繰り返す |
| `loop 回数 本体` | 回数だけ本体を繰り返す |
| `foreach 変数エントリ 一覧エントリ 本体` | 一覧エントリの単語を 1 つずつ変数エントリに入れて、本体を評価する |
| `? 文 文 ...` | 引数のうち 1 つを選んで評価する |
| `silent` | ここまでの結果を捨てる |
| `NULL` | 何もしない |

条件の判定では、空文字、`0`、`false` を偽とし、それ以外を真とする。

条件や本体の引数は、必要になるまで評価しない。それ以外のコマンドは引数をすべて先に評価してから実行する。

未定義のコマンドは空文字を返す。`loglevel` で有効にしていれば、未定義の関数として診断を出す。

## コマンド

次のコマンドは、通常の動作の同名のコマンドと意味が違うため、7 互換モードでは 7.5.0 の意味で動く。

| コマンド | 動作 |
|---|---|
| `expr 式` | 引数を 1 トークンずつ受け取る式の評価。下の「expr」を参照 |
| `test 式` / `[ 式 ]` | 条件の判定。結果は `true` か `false`。下の「test」を参照 |
| `array エントリ 番号` | 番号番目の単語を評価した結果を返す。範囲外は空文字 |
| `get エントリ 番号` | 番号番目の単語を、評価せずに逆コンパイルして返す。引数が 3 つでないときは空文字 |
| `enumerate エントリ` | 全部の単語を逆コンパイルして、空白で区切って返す |
| `textload ファイル エントリ` | テキストファイルを 1 行ずつ `エントリ.1` `エントリ.2` ... に読む。空の行は、その番号のエントリを空にする。全部が空の行でなければ、`エントリ.size` に行数を入れる。ファイルの文字コードは、BOM と内容で判定する (`locale` は使わない) |
| `readdir フォルダ エントリ` | フォルダの中のファイル名とフォルダ名を、エントリに入れる。`.` と `..` も入る。フォルダが無いときは、エントリを変えない |
| `split エントリ 文字列 区切り` | 文字列を区切りで分けて、`エントリ.1` `エントリ.2` ... に入れる。引数がこの 3 つでないときは、何もしない。空の要素は、その番号のエントリを空にする。全部が空の要素でなければ、`エントリ.size` に個数を入れる |
| `pirocall #ラベル [既定値]` | ピロ形式の辞書の、ラベルの単語を評価して返す。無ければ既定値を返す |

`set` `adddict` `clear` `size` `entry` `eval` `inc` `dec` `echo` `escape` `chr` `tolower` `toupper` `rand` `date` `load` `save` `savecrypt` `urllist` `saoriregist` `saorierase` `callsaori` は、通常の動作のコマンドが 7.5.0 と同じ結果を返すことを確かめてある。`set` と `adddict` は、値を 7 の文法で単語にする。`callsaorix` は、結果のエントリに値を文字列としてそのまま入れる点だけが違う (「7.5.0 との意図した違い」の 2 を参照)。通常の動作にあって 7.5.0 に無いコマンド (`function` `setstr` など) も使える。

### expr

引数 (`expr` の後ろの単語) を、1 つずつ演算子とオペランドとして読む。優先順位は低い順に次のとおりである。

1. `|` : 左が偽なら右、それ以外は左を返す
1. `&` : どちらかが偽なら空文字、それ以外は左を返す
1. `<` `<=` `=` `==` `!=` `>=` `>` : 結果は `1` か空文字。両方が整数に見えれば数値で、そうでなければ文字列で比べる
1. `+` `-`
1. `*` `/` `%` : 右結合である (`8 / 4 / 2` は `8 / (4 / 2)`)
1. `quote 文字列` / `length 文字列` / `find 文字列 部分` / `findpos 文字列 部分` / `index 文字列 文字集合` / `substr 文字列 開始 長さ`
1. `( 式 )` と、そのままのオペランド。閉じ括弧の `)` は `$( )` の終わりと区別するために、引用符で囲んで `")"` と書く

整数に見えるかどうかは先頭の 1 文字だけで決める (数字か `-` か、空文字)。整数に見えないオペランドで算術をしたとき、0 で割ったとき、引数が余ったときは、空文字を返す。整数は 64bit の符号付きで、範囲を超えた `+` `-` `*` は 64bit で回り込む (7.5.0 は 32bit。「7.5.0 との意図した違い」を参照)。

### test

`test 値` は値が真なら `true` を返す。`test ! 値` は否定である。`test 左 演算子 右` の演算子は `==` `=` `!=` `<` `>` `<=` `>=` (文字列の比較)、`-eq` `-ne` `-lt` `-gt` `-le` `-ge` (整数の比較)、`&&` `||` である。他の形は `false` を返す。`[ ... ]` は、最後の `]` を無視して `test` と同じに動く。

## 9 の文法を取り込む範囲

7 互換モードのゴーストでも、次の 2 つの範囲は通常の動作の文法 (Phase 8・9) で読んで実行できる。

- `=kis` の行から `=end` の行までの範囲 (KIS ゾーン)
- 単語の中の `$[ ... ]` (演算式)。`$[` から、対応する `]` までを 1 つの式として、通常の動作の文法で読む。引用符 (`"` と `'`) の中の `]` と、`${ }` や `$( )` の中の `]` は、対応に数えない

取り込んだ範囲の中は最後まで通常の動作の文法である。KIS ゾーンの中の `if` や `textload` などは通常の動作の意味で動く。取り込んだ範囲の外にある 7 の文は、7 の意味のままである。

7 互換モードで単語の中に `$[` と書くと、`$[` から式として読む。7.5.0 のように文字列として使いたいときは、`"$["` のように引用符で囲む。

## SHIORI

7 互換モードは SHIORI/3.0 で動き、SHIORI/2.x の要求も受け付ける。本体は `GET Version` への応答の先頭行のバージョンで 2.x か 3.0 かを決めるので、`GET Version SHIORI/2.6` には `SHIORI/3.0 200 OK` を返して、本体に 3.0 を選ばせる (7.5.0 は `SHIORI/2.6 200 OK` を返した)。2.x のほかの要求への応答の先頭行は `SHIORI/2.6` で始める。

要求は、`Charset` ヘッダの文字コードで読み、応答も同じ文字コードで返す。扱えるのは Shift_JIS・UTF-8・EUC-JP・ISO-2022-JP・EUC-KR・GB2312・Big5・ISO-8859-1 で、名前の書き方は [textload_charset](../kis/textload_charset.md) と同じである。`Charset` が無いときと、知らない名前のときは Shift_JIS とする。辞書の `locale` とは関係が無い (`locale` は辞書の読み込みだけに使う)。

SHIORI/3.0 の要求 (`GET SHIORI/3.0` / `NOTIFY SHIORI/3.0` と `ID` ヘッダを持つもの) は、次の表のとおり 2.x の要求に読み替えて、下の表と同じ動作で処理する。応答の先頭行は `SHIORI/3.0` で、文の本体は `Value` ヘッダに入れる。`GET` の `ID` に半角の大文字 (A-Z) が 1 つでもあればイベント、全部小文字 (数字・記号は問わない) ならリソースである。7.5.0 は 3.0 の要求に `SHIORI/2.6 400 Bad Request` を返したので、これは 7.5.0 との違いである。

| 3.0 の `GET` の `ID` | 読み替え先 |
|---|---|
| `OnCommunicate` | `GET Sentence` (COMMUNICATE)。`Reference0` を `Sender`、`Reference1` を `Sentence` とする |
| `OnTeach` | `TEACH`。`Reference0` を `Word` とする |
| `OnTranslate` | `TRANSLATE Sentence`。`Reference0` を `Sentence` とする。空なら `204` を返す |
| `\` で始まるもの (`\ms` など) | `GET Word`。`ID` を `Type` とする |
| `getaistate` / `getaistateex` | `GET Status`。`getaistateex` の `Reference0` が 1 以上なら `204` を返す (AI の状態は 1 組だけ) |
| 大文字を含むその他のもの (`OnBoot` `ShioriEcho` `KawariCommand` など) | `GET Sentence` (`Event` あり)。`ID` を `Event` とする |
| 全部小文字のもの (`homeurl` `sakura.recommendsites` など) | `GET String`。`resource.ID` を評価する。空のときは、`version` `craftman` `craftmanw` `shioriid` `name` に限り、華和梨が答える |

3.0 のイベントの `Reference` は、8 個より多くても `system.Reference0`〜 に全部入れる (2.x は 0〜7 だけである)。resource (`GET String` に読み替えるもの。`inputbox.autocomplete` など) も、`resource.ID` を評価する前に `Reference` を `system.Reference0`〜 に入れる。要求に無い番号は空にする。

3.0 の `NOTIFY` は `204` を返す。`ID` が `ownerghostname` なら `Reference0` を `system.Ghost` に入れて `system.OnNotifyGhost` を、`otherghostname` なら各 `Reference` (`ゴースト名\1サーフェス\1サーフェス` の形) を `system.OtherGhost` と `system.OtherGhostEx` に入れて `system.OnNotifyOther` を評価する (2.x の `NOTIFY OwnerGhostName` / `NOTIFY OtherGhostName` と同じ)。`hwnd` なら `Reference0` を本体のウィンドウとして覚える。どの `ID` でも、`Reference` を `system.Reference0`〜 に、`ID` を `system.EventName` に入れて、`event.ID` があれば評価する (結果は使わない。`system.OnEventUnknown` は評価しない)。

要求の値は次の表のとおり、`system.` で始まる小文字のエントリに格納する。通常の動作のように、全部のヘッダを `System.Request.*` に格納することはしない。`System.Callback.*` も、7 互換モードでは使わない。要求の値は、文字列としてそのまま格納し、`${` や `$(` は展開しない。

| 要求 | 動作 |
|---|---|
| `GET Version` | `ID` `Craftman` `Version` を返す |
| `GET Sentence` (`Event` あり) | `Reference0`〜`Reference7` を `system.Reference0`〜`7` に、イベント名を `system.EventName` に入れる。`event.イベント名` を評価し、無ければ `system.OnEventUnknown` を評価する。どちらも空なら `204` を返す |
| `GET Sentence` (`Sentence` あり) | COMMUNICATE である。`system.Sentence` `system.Sender` `system.Age` `system.Surface` に入れ、`system.Response0`〜`7` を空にして、応答を選ぶ。応答は、`system.OnResponse`、`event.Response`、マッチエントリ、`system.OnResponseUnknown`、`system.response.unknown` の順に、最初に空でなかったものである |
| `GET Sentence` (`Word` あり) | `Word` を `system.Sentence` に入れて、COMMUNICATE と同じに応答を選ぶ |
| `GET Sentence` (どれも無い) | `sentence` を評価する。空なら `204` を返す |
| `GET Word` | `Type` の先頭の 1 文字を除いた名前 (`\ms` なら `ms`) の `compatible.名前` を評価して返す。空なら `204` |
| `GET Status` | `system.OnGetStatus` を評価して返す。空なら、単語数・エントリ数・マッチエントリ数・バージョン・`100`・`100` をカンマで区切って返す |
| `GET String` | `ID` を `system.ID` に入れて、`resource.ID` を評価して返す。空なら `204` |
| `TEACH` | `Word` を `system.Sentence` に入れて、`system.OnTeach` を評価して返す |
| `TRANSLATE Sentence` | `Sentence` を `system.Sentence` に入れて、`system.OnTranslate` を評価して返す。空なら `400` |
| `NOTIFY` / `NOTIFY Ghost` / `NOTIFY OwnerGhostName` | `Ghost` を `system.Ghost` に入れ、`system.OnNotifyGhost` を評価する |
| `NOTIFY OtherGhostName` | `Ghost` を `system.OtherGhost` に、`GhostEx` を `system.OtherGhostEx` に入れ、`system.OnNotifyOther` を評価する |

`GET Sentence` の応答ではほかに次のことを行う。

- 話しかける相手は `system.communicate` の最初の単語で、無ければ要求の `Sender` である。`system.communicate` は読んだあとで空にする。`stop` は話しかけるのをやめる。応答が `200` で、相手が `NOTIFY OtherGhostName` で通知されたゴーストのときは、応答に `To` (相手)、`Sender` (自分のゴースト名)、`Reference0`〜`7` (`system.Response0`〜`7` の最初の単語)、`Age` を付ける。`Age` は、相手が要求の `Sender` と同じで、要求に `Age` があるときは、その値に 1 を足したもので、それ以外のときは `0` である。足した値が 20 以上になるときは、話しかけない。
- `system.BalloonOffset` に単語があれば、応答の `BalloonOffset` ヘッダに入れて、そのエントリを空にする。この処理はどの要求の応答でも行う。

## セキュリティ

要求の `SecurityLevel` ヘッダで、伝達経路を決める。`local` は local、`external` は external で、これら以外 (ヘッダが無いときを含む) は unknown である。大文字と小文字は区別しない。`Sender` ヘッダの末尾が `local` なら `(local)`、`external` なら `(external)` のときは、それを取り除いて `system.Sender` に入れる。

`security` のレベルによって、次の伝達経路の要求だけを処理する。処理しない要求には `400 Bad Request` を返す。

| レベル | 処理する伝達経路 |
|---|---|
| 0 | local・unknown・external |
| 1・2 (既定は 2) | local・unknown |
| 3 | local |

本体への送信 (`getproperty` `executesstp` と SAORI over DirectSSTP) は、local の要求を処理しているときだけ許す。

## 7.5.0 との意図した違い

7 互換モードは次の点で 7.5.0 と違う。

1. `ver` は、実行している華和梨のバージョンを返す (7.5.0 のバージョンは返さない)。`GET Version` の `ID` `Craftman` `Version` と、`GET Status` のバージョンも同じである。
1. 要求の値と SAORI の応答の値は文字列としてそのまま格納する。7.5.0 はこれらを単語として読んだため、引用符が消えたり、`${` や `$(` が実行されたりした。例外は `debug : debugger` を有効にしたゴーストの `ShioriEcho` と `KawariCommand` の `Reference0` である。この値は 7.5.0 と同じく単語として読んで評価する。
1. `save` と `savecrypt` は UTF-8 (BOM あり) で書く。7.5.0 が書いた Shift_JIS のセーブデータは、そのまま読める。
1. `GET Status` の単語数とエントリ数は、内部での単語の持ち方が違うため、7.5.0 と同じ数にならない。
1. 辞書の単語の中の `$[` は式として読む (「9 の文法を取り込む範囲」を参照)。
1. `GET Version` に `SHIORI/3.0` で答え、SHIORI/3.0 の要求 (`GET` / `NOTIFY` の `ID` ヘッダ) を受け付けて、`SHIORI/3.0` で答える (「SHIORI」を参照)。7.5.0 は `GET` に `400 Bad Request` を返し、`NOTIFY` は 2.x の `NOTIFY` として `Ghost` ヘッダだけを見た。
1. `expr` と `test` の文字列の大小は UTF-16 の並び順で比べる (7.5.0 は Shift_JIS のコードの並び順)。`expr` の `length` `substr` `index` は UTF-16 の 1 要素を 1 文字として数える。ASCII だけなら 7.5.0 と同じである。
1. `Sender` ヘッダの接尾辞は付いているときだけ取り除く。
1. `debug : log` の記録の書式は通常の動作のもので、7.5.0 の `kawari.log` とは違う。
1. SAORI を呼ぶときは、通常の動作の SAORI の仕組みを使う。`GET Version` を UTF-8 で問い合わせ、応答の `Charset` に従う (上の SHIORI と同じ文字コードを扱える)。`Charset` の無い SAORI には以後 Shift_JIS で送る。
1. `kosui --check` の静的検査 (`K-W2001` など) は 7 の単語を調べない。
1. `expr` の `+` `-` `*` `/` `%` と比較、`test` の `-eq` `-ne` `-lt` `-gt` `-le` `-ge` は、整数を 64bit で扱う (7.5.0 は 32bit だった)。32bit の範囲に収まる値の結果は 7.5.0 と同じである。範囲を超える値は、7.5.0 では 32bit で回り込んでいたが、64bit で回り込む (`expr 2147483647 + 1` は 7.5.0 では `-2147483648`、7 互換モードでは `2147483648`)。

## 実装していないもの

- `include` の入れ子は 16 段までである。7.5.0 は互いに `include` すると終わらなかった。
