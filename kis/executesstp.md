# executesstp

**Category:** 本体との連携

## 書式

```
executesstp コマンド [ 引数 引数 ... ]
```

## 戻り値

応答の追加データの1行目。応答コードが200番台でないとき、追加データがないとき、送れなかったときは空文字列

## 解説

本体にSSTPの`EXECUTE`を送り、その応答を受け取る(Phase 9.0.0 β2以降)。`Command:`にコマンド(`GetVersion`、`GetNames`など)を、引数を`Reference0:`、`Reference1:`...に入れて送る(`Charset`はUTF-8)。コマンドの種類は、本体のドキュメント(SSPならUKADOCのSSTPの仕様)を参照。

実行するたびに、次のエントリが書き換わる。

- `System.SSTP.ResponseCode`:応答コード。200=成功、204=成功したが返す値がない、400や501など=本体が受け付けなかった、0=送れなかった・応答がなかった
- `System.SSTP.Data`:追加データ(1行を1単語として格納。無ければ空)

0になるのは、本体のウィンドウがまだ分からないとき(NOTIFY hwndの前)、コマンドや引数が空、またはコマンドや引数に改行を含むとき(ヘッダを書き換えられてしまうため送らない)、SecurityLevelがlocal以外のリクエストの処理中のとき、本体が5秒以内に応答しないとき。理由はログに出る。

SSPはSHIORIをメインスレッドとは別のスレッドから呼ぶため、メインスレッドがSHIORIの処理を待っているときは`EXECUTE`に応答できず、最大5秒待たされて0になる。大事な処理では応答コードを確かめること。

## 使用例

```
sentence : 本体は$(executesstp GetVersion)です。
```
